# Build safety and recovery

`Project.build()` cleans the configured temporary directory before copying assets. Steps run sequentially there. The first failed flow or runner stops the build and rejects its promise; the original working directory is restored on every exit. The current build output and successful manifest are preserved if staging fails.

After all steps succeed, Bao prepares a sibling output directory and a new manifest. It records an `in_progress` transaction in `.bao.build-state.json`, renames previous output and manifest to backups, publishes the prepared files, and atomically marks the transaction `success` before removing backups. The published manifest also records `status: "success"`. If publication fails, the previous output and manifest are restored. If the process is interrupted, the next build with the same output configuration rolls back an unfinished transaction or cleans up an already committed transaction before loading the manifest. Leave the journal and backups together for recovery.

Publication uses sibling paths (`<buildPath>.bao-stage`, `<buildPath>.bao-backup`, `.bao.manifest.stage.json`, and `.bao.manifest.backup.json`). These names are reserved; Bao refuses to delete pre-existing reserved paths without its recovery journal. Consumers may briefly observe a missing output directory during the rename sequence. Recovery handles process interruption; it does not promise durability across filesystem or hardware failures.

Nested relative `tmpPath`, `assetsPath`, and `buildPath` values are supported. Relative asset and output paths must stay inside the temporary build directory. Absolute `tmpPath` is supported; absolute asset/output configuration uses the path's basename inside staging, so flow destinations should use that basename (for example `build`, for `/srv/site/build`). Paths that overlap the project root, assets, output, temporary directory, or persistent cache unsafely are rejected before cleanup, including aliases through existing symlinks.

Flows can optionally accept a `FlowContext` with the original `projectRoot`, persistent `.bao_cache` path, and manifest `dependencies` map. The cache survives staging cleanup. Only one Project build may run at a time within a process because flow execution uses the process-wide working directory. Custom flows and runners must write build artifacts into staging rather than directly into the live output directory.
